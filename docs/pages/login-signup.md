# 로그인 / 체험하기 (기술 준비 사항)

> 이 항목은 콘텐츠 페이지가 아니라 **기능 요구사항 메모**입니다 — 로그인은 실제 계정
> 시스템(백엔드 인증)이 있어야 의미가 있어서, 지금 로컬 전용 단계에서는 UI만 만들어봐야
> 가짜 기능이 됩니다. 클라우드 전환을 실제로 시작할 때 아래 결정부터 필요합니다.

## 결정이 필요한 것

- 인증 방식: 이메일/비밀번호 vs 소셜 로그인(구글 등) vs 둘 다 — [T.B.D]
- 인증 구현체: 직접 구현 vs 인증 서비스(예: Auth0, Clerk, Supabase Auth 등) 사용 — [T.B.D]
- 계정과 로컬 프로젝트 데이터의 관계: 클라우드 계정에 로컬 프로젝트를 연결/동기화할지,
  완전히 별도로 둘지 — [T.B.D]
- "체험하기"(Vrew의 게스트 체험 방식)를 로그인 없이 제공할지 — [T.B.D]

## 참고 (vrew.ai)

상단 내비게이션에 "로그인"과 "체험하기"(CTA 버튼), "무료 다운로드"(CTA 버튼)를 나란히
배치 — 클라우드 체험과 로컬 다운로드 두 경로를 동시에 제공하는 구조.

- 백엔드에 사용자/세션 모델 없음(`backend/app/models/schemas.py`는 `Project`/`MediaItem` 등
  프로젝트 데이터 모델만 존재).
- 프론트엔드에 인증 화면/라우팅 없음.

실제 착수 시 별도 설계 문서(인증 흐름, 세션 관리, 로컬 프로젝트와의 관계)를 먼저 작성하는
것을 권장합니다 — 지금 로드맵 항목(#27~40)과는 별개로 다뤄야 할 정도로 범위가 큽니다.
